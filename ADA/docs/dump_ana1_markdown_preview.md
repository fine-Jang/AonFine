## 2. 원문 자체의 특이사항 (제가 만든 게 아니라 원본에 이미 있는 것)

- **문서 제목이 "ㅅ"** 입니다 (content.hpf의 `<opf:title>`, 그리고 본문 맨 끝에도 낙서처럼 "ㅅ" 한 글자가 남아 있습니다).
  즉 이 파일은 정식 제출용 완성 보고서가 아니라 **레이아웃을 빠르게 잡아본 초안/스켈레톤**으로 보입니다.
  작성자 메타데이터는 "JHW", 생성 2026-09-09 08:39(UTC), 수정 2026-09-09 16:13(UTC)입니다.
- **같은 스레드의 점유량 수치가 3곳에서 다릅니다**: "2.8GB"(1절), "2.77 GB (67.96%)"(problem suspect 박스), "2.28gb"(결론).
  제가 임의로 통일하지 않고 **원문 그대로 3곳 다 다르게** 옮겼습니다. 실제 분석 자동화가 필요한 이유를 보여주는 대목이기도 합니다.
- "the thread org~~~", "class name ~~~", "total : 20 entries ~~" 등은 **원문에도 "~~~"로만 되어 있는 자리표시자**이며,
  제가 내용을 지어내지 않았습니다 — 실제 클래스명/스레드명/수치는 원본에 없습니다.
- 본문 전체가 굵게/색으로 강조된 곳이 없습니다(문단 스타일 ID는 몇 군데 다르지만 글자 속성은 전부 기본값). 즉 "결론" 문장도 시각적으로 강조되어 있지 않은 **평문**입니다.

## 3. 이미지 관련 사실 (추측 아님, 실제 확인한 것)

- ZIP으로 열어 `META-INF/manifest.xml`과 `Contents/section0.xml`을 확인한 결과, 이 문서에는 **내장된 래스터 이미지(BinData)가 하나도 없습니다.**
- "Heap dump Overview" 아래 있는 도형은 그림이 아니라 **HWP 벡터 도형(타원, `shapeComment="타원입니다."`)** 이고, 채우기/선이 모두 투명이라 인쇄하면 사실상 안 보입니다.
- 결론: 이 예시 문서 한 건만 보면 "이미지를 어떻게 옮길지"는 아직 실증할 대상이 없습니다.
  하지만 문서의 의도(스크린샷을 붙일 자리를 남겨둔 것)로 보면, **실제 완성된 보고서에는 히프덤프 개요 차트나 스레드 덤프 스크린샷 같은 이미지가 들어갈 가능성이 높습니다.**
  Markdown은 이미지를 문서 안에 내장하지 못하므로, 그런 경우 PNG 등 **별도 파일로 저장 후 `![]()`로 링크(별첨)**하는 방식이 되어야 합니다 — 이미지가 실제로 등장하는 예시가 오면 다시 확인이 필요합니다.

## 4. Markdown으로 재현되는 것 / 달라지는 것

**그대로/거의 그대로 재현되는 것**
- 상단 사업명/기관명/요청자/업무명/작업일자/작업내용 메타데이터 → 표
- "1. 증상 / 2. 분석 내용 / 3. 결론(권고사항)" 같은 순번 텍스트 → 그대로 텍스트 또는 제목(`##`)으로 승격 가능(원문엔 실제 제목 스타일이 없었으므로 오히려 Markdown 쪽이 더 명확한 구조를 가짐)
- "&lt;problem suspect 1&gt;", "thread overview" 같은 강조 박스 → 인용구(`>`)나 코드블록으로 근사 재현 가능
- 스택트레이스/서버로그 자리 → Markdown 코드블록(```)이 원문의 빈 텍스트보다 오히려 가독성이 좋음(고정폭 폰트)

**달라지거나 손실되는 것**
- 표 셀 병합(rowspan/colspan): 원문은 "작업일자/작업내용" 행이 3칸을 병합해 넓게 쓰지만, 표준 Markdown 표는 병합을 지원하지 않아 위처럼 빈 칸(`|||`)으로 흉내내는 수준에 그칩니다.
- 강조 박스의 테두리/음영: 원문은 표 테두리(검정 실선, `borderFillIDRef="3"`)로 시각적 박스를 만들지만, Markdown 인용구/코드블록은 테두리가 아니라 들여쓰기나 배경색(렌더러에 따라 다름)으로만 표현됩니다.
- 고정 페이지 크기/여백(HWPUNIT 단위의 용지폭 59528 x 84186, 여백 등): Markdown은 흐르는(reflow) 텍스트라 "이 보고서는 정확히 1페이지"라는 보장이 없습니다. 나중에 PDF로 인쇄해야 한다면 별도 CSS/변환 규칙이 필요합니다.
- 이미지: 위 3절대로 이 예시엔 실물 이미지가 없어 손실이 없지만, 향후 실제 이미지가 포함된 보고서라면 문서 내장이 아니라 "별첨 파일 + 링크"로 바뀝니다.

### 근거(Worker/MAT가 사실로 제공 가능) vs 해석(Claude 판단이 필요) 구분
